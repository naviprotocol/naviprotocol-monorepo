title: Withdraw
---

The withdraw builder appends vault withdrawal calls to a transaction you provide. It dispatches by `vault.source`, plans which of the owner's receipts to draw from, and — for NAVI — merges the results into a single coin.

## Core Features

- **Three Target Forms**: Withdraw by amount, by raw share count, or everything
- **Automatic Receipt Planning**: Splits the request across receipts, smallest-first
- **Eligibility Filtering**: Skips Volo receipts that are locked or already have a pending request
- **Insufficient-Balance Safety**: Throws rather than silently withdrawing less than requested

`client` is optional — it defaults to the public mainnet fullnode; pass your own for a private endpoint.

## API Reference

### withdrawPTB

Build a withdrawal from a vault. See [documentation](/typedoc/functions/_naviprotocol_vault.withdrawPTB.html) for details.

**Usage Example**

```typescript
import { withdrawPTB } from '@naviprotocol/vault'
import { Transaction } from '@mysten/sui/transactions'

const tx = new Transaction()

// By amount — human-readable decimal string in vault coin units
await withdrawPTB(tx, vault, owner, { kind: 'amount', amount: '1.5' })

// By raw share count — the unit VaultPosition.shares reports
await withdrawPTB(tx, vault, owner, { kind: 'shares', shares: '1000000' })

// Everything the owner's receipts hold
await withdrawPTB(tx, vault, owner, { kind: 'all' })
```

**Parameters**

- `tx`: The transaction to append calls to
- `vaultIdentifier`: A vault id or an already-fetched vault object
- `owner`: Sui address whose receipts are drawn from
- `target`: What to withdraw — see the three forms below
- `options.client`: gRPC client for on-chain reads

## Withdraw Targets

```typescript
type WithdrawTarget =
  | { kind: 'amount'; amount: string } // human-readable decimal string
  | { kind: 'shares'; shares: string | bigint } // raw on-chain share count
  | { kind: 'all' } // everything available
```

- **`amount`** — a decimal string in vault coin units, matching the string form accepted by
  `depositPTB`. Must be positive and within the coin's precision.
- **`shares`** — a raw share count, the unit `VaultPosition.shares` reports. Accepts a string or a `bigint`. Must be greater than zero.
- **`all`** — drains what is available.

<Callout>
  For Volo, `{ kind: 'all' }` covers only the receipts eligible **right now**. Receipts still inside
  the withdraw lock, or already carrying a pending withdraw request, are skipped — so "all" can
  withdraw less than the wallet's total shares. Check
  [`getPendingRequests`](/vault/pending-requests) if the result looks short.
</Callout>

## Consuming the Result

The return type differs by source, and this is the single most important difference between the two:

| Source | Returns                                     | Settlement                            |
| ------ | ------------------------------------------- | ------------------------------------- |
| NAVI   | `TransactionResult` — the withdrawn coin    | Immediate, same transaction           |
| Volo   | `TransactionResult[]` — created request ids | Asynchronous, executed by an operator |

```typescript
import { withdrawPTB } from '@naviprotocol/vault'
import { Transaction, TransactionResult } from '@mysten/sui/transactions'

const tx = new Transaction()

if (vault.source === 'navi') {
  // A coin you must consume
  const coin = (await withdrawPTB(
    tx,
    vault,
    owner,
    { kind: 'amount', amount: '1.5' },
    { client }
  )) as TransactionResult
  tx.transferObjects([coin], owner)
} else {
  // Request ids — droppable u64s, nothing to consume.
  // The principal arrives later, when an operator executes the request.
  const requestIds = (await withdrawPTB(
    tx,
    vault,
    owner,
    { kind: 'shares', shares: '1000000' },
    { client }
  )) as TransactionResult[]
}
```

<Callout type="warn">
  A NAVI withdrawal hands you a coin that Sui requires you to consume — transfer it, or the
  transaction will fail. A Volo withdrawal returns nothing you need to consume, and moves no
  principal in this transaction.
</Callout>

## Receipt Planning

A wallet can hold several receipts for one vault. Both implementations consume them **smallest-first**, which retires dust receipts before touching a large one and keeps the call count down. A single `withdrawPTB` may therefore append several on-chain calls:

- **NAVI** merges the resulting coins, so you always get exactly one coin back.
- **Volo** creates one request per receipt drawn from, so you get one request id per receipt.

If the owner's receipts cannot cover the request, the builder throws `INSUFFICIENT_BALANCE` rather than withdrawing less than you asked for. For Volo, the error's `details.excludedReceipts` lists which receipts were skipped and why:

```typescript
import { withdrawPTB, isVaultSdkError } from '@naviprotocol/vault'

try {
  await withdrawPTB(tx, vault, owner, { kind: 'amount', amount: '1000' }, { client })
} catch (error) {
  if (isVaultSdkError(error) && error.code === 'INSUFFICIENT_BALANCE') {
    console.log(error.details?.uncoveredShares) // or uncoveredAmount for NAVI
    console.log(error.details?.excludedReceipts) // Volo: [{ id, reason }]
  }
}
```

## Volo Withdrawal Constraints

The Volo contract rejects a withdrawal in two cases, so the SDK excludes those receipts from planning up front:

1. **A withdraw request is already pending** on that receipt.
2. **The withdraw lock has not expired** — a receipt is locked for `locking_time_for_withdraw` after its last _executed_ deposit.

Both show up in `details.excludedReceipts` when the remaining receipts cannot cover the request.

## Unit Conversion Caveats

The two protocols burn different things on-chain, and the SDK converts for you:

- **NAVI** withdraws by **asset amount**. A `shares` target is converted at the vault's current on-chain exchange rate before planning.
- **Volo** burns **shares**. An `amount` target is converted from the API's `totalStaked`/`totalShares` snapshot.

<Callout>
  For Volo, that conversion is an **estimate**. The request settles at whatever rate the operator
  executes it at, which may differ from the snapshot the SDK converted against. Use
  `{ kind: 'shares' }` when you need an exact share count burned.
</Callout>

## Errors

| Code                   | Cause                                                                 |
| ---------------------- | --------------------------------------------------------------------- |
| `INVALID_AMOUNT`       | The target holds a non-positive or unparsable value                   |
| `INSUFFICIENT_BALANCE` | The owner's receipts cannot cover the request                         |
| `VAULT_NOT_FOUND`      | No vault matches the given id                                         |
| `VAULT_UNSUPPORTED`    | The vault's source has no withdrawal builder                          |
| `VAULT_CONFIG_INVALID` | An `amount` target could not be priced from the vault's totals (Volo) |

See [Error Handling](/vault/errors) for how to branch on these.
