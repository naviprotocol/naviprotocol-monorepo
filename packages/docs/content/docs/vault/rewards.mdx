---
title: Rewards
---

The rewards module reads a wallet's claimable vault rewards and builds the calls to claim them. See the API reference for [`getVaultRewards`](/typedoc/functions/_naviprotocol_vault.getVaultRewards.html) and [`claimRewardsPTB`](/typedoc/functions/_naviprotocol_vault.claimRewardsPTB.html).

<Callout>
  Vault rewards are a **NAVI-only** feature. Volo vaults have no receipt reward ledger, so
  `getVaultRewards` returns an empty array for them and there is nothing to claim.
</Callout>

## Reading Rewards

`getVaultRewards` returns one entry per (receipt, reward coin type) pair — the granularity claiming happens at. Each entry carries `claimable`, `claimed`, the `receipt` it is credited to, and the `vault`, so a list can span several vaults.

```typescript
import { getVaultRewards } from '@naviprotocol/vault'

const rewards = await getVaultRewards(vault, '0x...')
```

<Callout type="warn">
  `claimable` counts only **settled** rewards. An actual claim settles first and then pays, so it
  hands out more than this figure — entries with `claimable: 0n` may still be worth claiming. Do not
  filter on `claimable > 0n` to decide whether to claim.
</Callout>

## Claiming

`claimRewardsPTB` returns an array of `{ coin, coinType }`, one entry per **distinct reward coin type** across the rewards you passed in. Payouts from different receipts sharing a coin type are merged into one coin.

```typescript
import { getVaultRewards, claimRewardsPTB } from '@naviprotocol/vault'
import { Transaction } from '@mysten/sui/transactions'

const tx = new Transaction()
const rewards = await getVaultRewards(vault, owner, { client })

const claimed = await claimRewardsPTB(tx, rewards, { client })

for (const { coin } of claimed) {
  tx.transferObjects([coin], owner)
}
```

<Callout type="warn">
  The returned coins are unconsumed — transfer them, or the transaction will fail.
</Callout>

`claimRewardsPTB` accepts rewards spanning several vaults and harvests each distinct vault once, so a whole portfolio can be claimed in one transaction:

```typescript
import { getPositions, getVault, getVaultRewards, claimRewardsPTB } from '@naviprotocol/vault'

const positions = await getPositions(owner)

// Only NAVI-served vaults have rewards
const allRewards = (
  await Promise.all(
    positions
      .filter((position) => position.source === 'navi')
      .map(async (position) => getVaultRewards(await getVault(position.vaultId), owner, { client }))
  )
).flat()

const claimed = await claimRewardsPTB(tx, allRewards, { client })
```

## Why Figures Look Stale

Before claiming, `claimRewardsPTB` harvests each vault's active market reward rules, advancing their on-chain indices. Without this, rewards sitting unharvested in the underlying lending market would be invisible and unclaimable. Deposits and withdrawals harvest too, so a claim bundled after either one in the same transaction already works from current indices.

Reward figures otherwise inherit the contract's own staleness:

- **Market rules** only advance on harvest. Rewards accrued in the underlying lending protocol since the last one are not yet reflected.
- **Vault-native rules** (funded by admin deposits) only advance when someone interacts with the vault.

This is why `claimable` understates what a claim actually pays: the claim harvests and settles first.

Failures throw `VAULT_UNSUPPORTED` (the reward's vault is not a NAVI vault), `VAULT_CONFIG_INVALID` (a rule's pool or reward fund could not be resolved), or `CHAIN_QUERY_FAILED`. See [Error Handling](/vault/errors).
