# Multiply：原生质押兑换率初值实现与验收

2026-11-24（Asia/Singapore）。分支 `zado/multiply-package`，基线 `0e8f2a9`，当前为本地未提交改动。未发布、推送或部署。本文件是上一版 price-only 优化之后的最终实现报告。

## 实现与边界

- Volo/Haedal converter 新增可选 `getRateHint(pair)`：读取原生质押 getter 的净输出比例，包含质押费。Volo 沿用 `get_amount_out`；Haedal 按 deposit_fee 扣费后调用 `get_stsui_by_sui`。不使用赎回手续费代替质押费。
- 每个 converter 实例独立保存 5 秒提示值，由实例的 Sui client、固定池及币种方向确定作用域；不缓存钱包仓位、风险价格或可执行报价。TTL 从读取开始计时，不因读得慢而延长。
- 首次无快照时以 1 SUI 做只读探测；后续成功的真实原生 stake 报价会更新提示值。相同实例并发探测合并，pending 超过5秒可重试；较早开始的读取晚返回不覆盖较新读取。失败不缓存；赎回和 Astros DEX 路由不写入该缓存。
- SDK 客户端仅在当前转换方向有单个明确 provider 时选择它的提示值；多个候选 provider 时不猜测路线。未提供提示接口的路由保留价格/费用初值。
- 用户修改金额仍重新取得正式报价。快照过期、费用变化、原生路径暂停、实际输出偏离等情况下，继续走原有回退或错误路径。若 API 每次重新创建 converter，仍然是冷启动；本次没有修改 API 的实例生命周期。

## 计算

`r` 是每个借款币最小单位可取得的抵押币最小单位数量（净质押兑换率）；`pc/pd` 是协议每个最小单位价格；`C/D` 是现有抵押/债务；`P` 是本金；`L` 是目标杠杆。

```
a = (1 + flashFeeBps/10000) * (1 + borrowFeeBps/10000)
baseCollateral = C + (输入是抵押币 ? P : P*r)
F = floor((pc*baseCollateral*(L-1) - pd*D*L)
          / (pd*a*L - pc*r*(L-1)))
```

`r` 只用来估算兑换数量，**不替换任何协议风险价格**。无提示时 r=pd/pc。分母非正、初值负数或越界时跳过初值。正式金额仍经真实 converter 报价，并以实际费用取整重算：flash repayment 向上取整，borrow fee 向下取整。

接受候选前继续执行既有 `targetReached`、小本金残差要求和完整 `validateResult`：最低输出 HF/LTV/最大杠杆，闪电贷/借款/供应/同池现金容量，E-Mode 暂停/敞口和原 0.01% 杠杆容差。候选不满足就进入原 bracket 求解器；没有新一轮修正初值的迭代。

读取提示和转换尝试共用原32次/45秒预算（提示缓存命中也占一次尝试，不代表发生 RPC）。读取异常、损坏数据仍报错；原生路径的预期不可用可进入旧求解器和原有 Astros fallback。还款、补抵押、降低杠杆、平仓及 build 风险/资金检查未改。

## 回归测试与复核

377/377通过：此前339个通过，本次新增38个。TypeScript、ESLint、构建和格式检查均通过；ESLint仅有仓库既有的 React 自动检测提示。

新增覆盖：

- 开仓两种本金输入；已有仓位追加两种本金；已有仓位加杠杆；大仓位少量追加的本金相对精度。
- 非零质押费、flash fee、borrow fee 同时存在，逐项复核整数舍入与债务总额；协议价格1:1而真实净兑换率约0.9，HF必须仍按协议估值。
- 兑换率/费率快照不准确时直接回到原区间，非正分母不使用初值，提示不可用不跳过正式报价。
- 提示零值、币种错配、过期或读取错误不能变为合法资金计划；实际最低输出 HF 和闪电贷容量失败继续拒绝。
- 1 SUI转换门槛的下界、等值和上界：原生 converter 与 planner/路由集成均覆盖，缓存不绕过门槛，低于门槛仍走原 fallback。
- 原生费用计入 rate；并发只探测一次；实例隔离；5秒到期；正式报价更新费率；读取失败重试；旧 pending 过期允许新读取且晚返回不覆盖新结果；暂停后仍由正式报价拒绝原生路径。
- 提示请求悬挂仍受同一个45秒截止时间限制。此前最终风险检查、32次报价预算、6位资产退出和 build 资金回归继续通过。

人工复核：新比率仅进入 seed；最终风控函数和执行金额来源保持原有口径。提示不是交易授权或报价缓存。未增加账户状态缓存，也未改 E-Mode/HF 配置。

## 真实报价方法

- 完整 SDK quote，真实 Registry/Cap、市场、手续费和 converter；空公开账户0x…cafe，无签名、广播或资金变化。
- 原求解器从 `git show 0e8f2a9:packages/multiply/src/planner.ts` 获取。两组共享当前其余 SDK 模块，原求解器不调用新增提示接口。原始结果记录当前四个源文件 SHA256，并与最终源码核对一致。
- 100本金每策略3轮，交替旧/新执行顺序。新组每轮新建 engine，先测冷启动，再立刻用同一实例测一次后续请求；市场/Cap等仍实时读取。后续请求保持同本金以便对照，并非完整前端交互。
- 100000本金每策略1轮。所有目标2x、滑点50bps；金额单位分别为 SUI/SUI/USDC，不是统一美元金额。
- vSUI E-Mode0、USDSUI E-Mode2；haSUI延用当前基准普通main参数。本轮不修改部署配置。
- 统计 converter.quote 调用，明确分开 rate-probe 和 formal。冷探测通过同一被计数实例运行，耗时完整计入 SDK 总时间；一次converter调用本身包含若干底层RPC。
- 样本共36次（100本金27次+10万本金9次），全部成功。不是完整链上开仓模拟，也不是 API/Preview 页面耗时；API估值、保存、网络代理与前端防抖不在本次测量中。
